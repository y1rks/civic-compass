# scripts/kokkai — 発言データの収集と前処理

【1】utterances を作るための**元データ**を用意する部分です。
`CLAUDE.personalize.md` の「A. 議員プロファイル構築バッチ」のうち、①機械的フィルタまでを担当します。

```
国会会議録API ──→ collect.mjs    ──→ data/raw/{id}.jsonl       APIレスポンスそのまま
議員の公式サイト ─→ fetch-web.mjs  ──→ data/raw_web/{id}.jsonl   ページ本文
手打ちテキスト ──→（手で置く）    ──→ data/manual/{id}.md
                                          │
                                    preprocess.mjs
                                          ↓
                              data/clean/{id}.jsonl  ← LLM の segment分割・抽出の入力
                                          ↓
                              （未実装）segment分割 → フレーム抽出
                                          ↓
                                  【1】utterances (D1)
```

`data/` は `.gitignore` 対象です。スクリプトを実行すれば再生成できます。
ただし `data/manual/` だけは**手で作ったデータなので再生成できません**。
失いたくない場合は別途バックアップするか、リポジトリが非公開であることを確認した上で
`.gitignore` の `/data/` を絞ってください（公式サイトの文章は著作物です）。

## 使い方

```bash
# 国会会議録から収集（既存ファイルはスキップ。全15人で15〜25分）
node scripts/kokkai/collect.mjs
node scripts/kokkai/collect.mjs --only=P00007 --force   # 特定の議員を取り直す

# 公式サイトから政策・理念ページを取得
node scripts/kokkai/fetch-web.mjs
node scripts/kokkai/discover-web.mjs                    # 政策ページのURL候補を探す（補助）

# 前処理（何度でもやり直せます）
node scripts/kokkai/preprocess.mjs
```

## 設計上の約束

### 生データは無加工で残す

`data/raw/` は API レスポンスの `speechRecord` をそのまま1行1件で保存します。
前処理のルールは必ず変わるので、raw を残しておけば API を叩き直さずにやり直せます。
`utterances` を書き換えないのと同じ理由です。

同じ理由で、収集期間（`collect_from`）と抽出期間（`extract_window`）を分けています。
生データは広めに取り、抽出対象は `extract_window` で絞ります。

### 抽出期間は全議員で揃える

`extract_window` は **2020-08-01 〜 2026-08-22（5年）** で全議員共通です。
議員ごとに期間が違うと、データソースの期間差が思想の差として現れてしまいます。

閣僚経験者4人（高市・河野・小泉・斉藤）だけは `collect_from` を 2017-08-01 にしていますが、
これは**生データを広く持っておくため**で、抽出には使いません。

### 発言時点の会派・役職は API から取る

API の `speakerGroup` / `speakerPosition` は**その発言時点の値**です。
`party_at_time` / `position_at_time` はこれをそのまま使い、**LLM に推測させません**。
2026年の政党再編（立憲 → 中道改革連合など）があるため、現所属で集計すると事実として誤りになります。

### 政府答弁は「会議の種類」で重みを変える

政府答弁は官僚が作成した統一見解なので本人の価値観としては使えない——と考えがちですが、
実データで測ると**会議の種類によって全く違いました**。

高市早苗の答弁を種別に分け、定型表現（「お答えいたします」「適切に対応」「努めてまいります」等）
の出現率を測った結果：

| `answer_context` | 会議 | 定型表現率 | 平均字数 | 重み |
|---|---|---:|---:|---:|
| `spontaneous` | 質問する側の発言 | — | — | **1.0** |
| `party_leader_debate` | 国家基本政策委員会（党首討論） | 2.3% | 439 | **1.0** |
| `budget_committee_answer` | 予算委員会での答弁 | 7.0% | 389 | **0.5** |
| `ministry_committee_answer` | 各省委員会での答弁 | 10.6% | 446 | **0.3** |
| `plenary_answer` | 本会議での答弁 | **81.3%** | 2,642 | **除外** |

党首討論は原稿なしの応酬で、「成長する経済をつくらなきゃ財政は絶対に健全化しない**と私は思っております**」
のような一人称の価値表明が出ます。一方、本会議答弁は施政方針演説・法案の趣旨説明で、
「リスクの最小化の観点から資金面で万全の備えを取るものです」のように価値の言語がなく、
抽出すると全大臣が `efficiency_utility` 一色になります。

**この重み付けで、閣僚経験者のデータ量が実用水準になりました**（河野太郎 8件 → 重み付き387）。
各省委員会答弁の定型表現率は議員差が大きい（河野3.4% / 斉藤23.9%）ので、
実装順2のゲートで「答弁込み／答弁抜き」を比べて調整の余地があります。

### utterances のテキストは3層

| フィールド | 内容 | 用途 |
|---|---|---|
| `block_text` | 分割前の発言ブロック全文。**分割していない場合は `null`** | 切り落とした前後の文脈を見せる |
| `quote` | この segment の全文 | 引用として見せる単位 |
| `justification_frames[].evidence_text` | 根拠にした箇所（40〜150字） | なぜこのタグが付いたかの説明 |

`block_text` を分割時だけ持つのは、分割していないと `quote` と同じ文字列になって重複するためです。
クライアントは `block_text ?? quote` で常に発言ブロック全文を得られます。

`evidence_span` は **`block_text ?? quote` 上の絶対位置**なので、そのままハイライトに使えます。

```js
const full = u.block_text ?? u.quote;
const [s, e] = frame.evidence_span;
full.slice(s, e)   // → 根拠にした箇所
```

### 位置の基準は `text`

`preprocess.mjs` が出力する `text`（発言者名プレフィックスを剥がし、改行と行頭インデントを
正規化したもの）が、`char_range` / `evidence_span` の基準です。
剥がしたプレフィックスは `prefix_removed` に残してあるので、必要なら元の文字列に戻せます。

### 除外したブロックも残す

短すぎる発言や議事進行の定型文は `excluded_reason` を付けるだけで、レコード自体は消しません。
取りこぼしの監査に必要です。抽出対象は `excluded_reason === null` のものです。

| `excluded_reason` | 意味 | 件数 |
|---|---|---:|
| `too_short` | 200字未満 | 8,507 |
| `out_of_window` | `extract_window` の外 | 2,918 |
| `chair_procedural` | 委員長・議長・主査としての議事進行 | 1,270 |
| `plenary_government_statement` | 本会議での大臣答弁（施政方針・趣旨説明） | 367 |
| `procedural` | 「これより会議を開きます」等の定型文 | — |
| `government_official` | 政府参考人（官僚）としての発言 | — |

### 公式サイトは著作物なので `quotable: false`

国会会議録は公文書なので `evidence` に原文を引用できます（`quotable: true`）。
一方、議員個人サイトの文章は著作物なので、`CLAUDE.personalize.md` §10 のとおり
**要約＋出典リンク**で扱い、原文は表示しません。この区別を `quotable` で持っています。

### robots.txt は AI クローラー向けの指示にも従う

`fetch-web.mjs` は `civic-compass` という独自の User-Agent で動きますが、
収集したテキストは LLM に投げるので**用途としては AI クローラーそのもの**です。
そのため `ClaudeBot` / `GPTBot` / `CCBot` / `Google-Extended` 向けの `Disallow` にも従います。
独自 UA を名乗れば回避できてしまいますが、それはサイト運営者が表明した意思を
経路を変えて回避することになるためです。

現在、**高市早苗のサイト（sanae.gr.jp）が ClaudeBot を名指しで拒否**しているため自動取得していません。
その分は `data/manual/P00001.md` に手で投入されています。

## 抽出の設計

### LLM に文字位置を数えさせない

`char_range` / `evidence_span` を LLM に出力させると必ずずれます。代わりに
**「原文からの抜き出し」を返させて、位置の特定は `align.mjs` が `indexOf` で行います**。

これは精度対策であると同時に、品質保証の仕掛けでもあります。
原文に存在しない引用は照合で見つからないので、§6 の「推論でタグを付けない」
「evidence_span を示せないタグは付けない」が**機械的に強制されます**。
見つからなかったタグは `rejected_frames` に落とし、プロンプト改善の材料にします。

### パイロットの結果（実装順1）

50ブロック → 58セグメント → 134フレームで確認した結果：

| 指標 | 結果 |
|---|---|
| 引用が原文と厳密一致 | 134 / 134 |
| 原文になく破棄 | 0 |
| `override` の出現 | 12件（9%） |
| 価値含意なし | 7 / 58（12%） |

思想が対極の議員で frame 分布に差が出ることを確認しました（実装順2のゲート）。

```
高市早苗 vs 田村智子    主権・自立 20% vs  0%   ケア・被害 35% vs 20%
神谷宗幣 vs 天畠大輔    ケア・被害  4% vs 35%   主権・自立 17% vs  0%
```

同じ「外国人・移民」を田村智子は `beneficiary`、神谷宗幣は `threat` で語っており、
**セルキーから `role` を落とせない**ことがデータで確認できました。

## API を叩くときの注意

- `maximumRecords` は最大100。`nextRecordPosition` が null になるまでページング
- 1条件で1000件を超えるとエラー（`(19017) 検索件数が制限値1000件を越えました`）。
  `collect.mjs` は件数を先読みして期間を二分割で再帰的に切っています
- 短時間の大量アクセスは禁止。`REQUEST_INTERVAL_MS`（会議録1.2秒 / サイト2秒）を勝手に下げないこと
- 同姓同名の混入は `expected_groups`（想定会派）との突き合わせで警告します。
  警告が出たら `data/raw/{id}.meta.json` の `groups` を確認してください

### 現職でなくなった議員は `active: false` で残す

`politicians.json` の `active: false` は、現職でなくなった議員です。
データは残しますが、プロファイル構築とマッチ候補からは外します
（§10「プロファイルが未整備の議員は候補から除外するフラグを持つ」と同じ考え方）。

| 議員 | 状況 | 差し替え先 |
|---|---|---|
| 音喜多駿（P00009） | 2025-07-20 の参院選（東京）で落選 | 猪瀬直樹（P00016） |
| 山本太郎（P00013） | 2026-01 議員辞職、2026-07 政界引退 | 天畠大輔（P00017） |

**れいわ新選組は 2026年8月6日に党名を「いのちの党」に変更**しています。
新代表は山本譲司ですが国会発言が4件しかないため、共同代表の天畠大輔を採用しました。
発言時点の会派は `party_at_time`（API の `speakerGroup`）が持つので、旧党名の発言もそのまま使えます。

## 既知の課題

- **安野貴博・小川淳也は党サイト等で代替**しています。個人サイトが SPA で本文を取得できない、
  または政策ページに本文がないためです。2人とも党代表なので §8 の「1人の党は党首＝党」の
  近似に沿います
- **猪瀬直樹は公式サイトに政策文書がありません**（著作紹介が中心）。国会発言537件で補っています
- **web データの分量差が大きい**。稲田朋美29件16,176字に対し小泉進次郎は1件534字、猪瀬直樹は0件です。
  `share`（比率）で正規化する設計なので比較自体は可能ですが、`source_kind` で分離できるように
  してあります
- **web/manual と kokkai でフレームの出方が違う**可能性があります。公約は `care_harm` /
  `efficiency_utility`、質疑は `procedure_rule_of_law` が出やすいと予想されるため、
  `source_kind` で分離して正規化できるようにしてあります。実装順1・2で確認してください
- **安野貴博の参考人発言11件**（議員就任前、GovTech東京アドバイザーとして）が含まれています。
  `speech_type` の語彙に該当がないため「国会質疑」にし、`speaker_role: "参考人"` を生で残しています
